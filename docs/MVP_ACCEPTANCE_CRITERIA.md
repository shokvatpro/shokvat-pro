## 1. تعريف الـ MVP
> نسخة سعودية تعمل لمجمع واحد إلى ثلاثة مجمعات تجريبية، تستقبل واتساب ونماذج العملاء المحتملين والمكالمات الفائتة في صندوق وارد واحد، توزعها على الموظفين، تقيس زمن الرد، تحوّلها إلى مواعيد، وتعرض للمدير القمع من المصدر إلى الحضور — مع إدارة منصة تملكها شوكفات لإنشاء المجمعات وإدارة اشتراكاتها.

**الدولة:** السعودية فقط (`sa-1`). **اللغات:** العربية والإنجليزية كاملتين. **البيانات:** وهمية حتى اكتمال المرحلة 9.

## 3. معايير القبول الوظيفية (Given / When / Then)

### 3.1 المصادقة والصلاحيات
- **AC-AUTH-01** مدير مجمع بلا MFA عند أول دخول ← يُجبر على تفعيله قبل الوصول للوحة.
- **AC-AUTH-02** 10 محاولات دخول فاشلة خلال 15 دقيقة ← قفل مؤقت + سجل تدقيق.
- **AC-AUTH-03** موظف استقبال مقيّد بفرع الخبر يطلب محادثة من فرع الدمام بمعرفها ← 404.
- **AC-AUTH-04** أخصائي التسويق يفتح رابط محادثة ← مرفوض؛ يرى التقارير المجمعة فقط.
- **AC-AUTH-05** مدير المجمع يعطّل موظفًا ← تنتهي جلساته ولا يستقبل أحداثًا فورية خلال < 60 ثانية.

### 3.2 عزل المجمعات (حرج)
- **AC-ISO-01** إلى **AC-ISO-09**: كل الحالات في TENANT_SECURITY.md §7 تنجح آليًا في CI.
- **AC-ISO-10** مالك المنصة لا يستطيع عبر أي شاشة أو API قراءة محتوى رسالة أو بيانات عميل دون منحة وصول نشطة.

### 3.3 صندوق الوارد
- **AC-INB-01** رسالة واتساب واردة جديدة ← تظهر في قائمة «غير معيّن» أو للموظف المعيّن حسب القاعدة خلال < 3 ثوانٍ، بحالة `new`.
- **AC-INB-02** نفس الـ webhook يُرسل مرتين ← رسالة واحدة فقط.
- **AC-INB-03** الموظف يرد ← `first_responded_at` يُسجّل، FRT يُحسب بساعات العمل، الحالة `waiting_customer`.
- **AC-INB-04** مرور هدف SLA دون رد ← `sla_breached = true` + إشعار للمشرف + ظهور في فلتر «تجاوز SLA».
- **AC-INB-05** محاولة رد حر بعد انتهاء نافذة 24 ساعة ← الزر معطّل مع اقتراح قالب، والخادم يرفض الطلب إن تم تجاوز الواجهة.
- **AC-INB-06** ملاحظة داخلية مع إشارة @ ← لا تُرسل للعميل، وتُرسل إشعارًا للزميل.
- **AC-INB-07** عميل يرد على محادثة `resolved` ← تعود `open` لنفس الموظف.
- **AC-INB-08** البحث بجزء من الاسم العربي بأي شكل للهمزة أو برقم الجوال المحلي/الدولي ← يجد العميل.

### 3.4 العملاء والمسار
- **AC-CRM-01** رسالة من رقم موجود ← تُربط بنفس العميل، لا عميل جديد.
- **AC-CRM-02** نموذج TikTok برقم موجود بصيغة مختلفة ← اقتراح تكرار، ولا دمج تلقائي.
- **AC-CRM-03** دمج عميلين ← كل المحادثات والمواعيد تنتقل، والسجل يُوثّق الدمج، والدمج قابل للمراجعة.
- **AC-CRM-04** نقل العميل بين مراحل المسار ← يُسجّل في الخط الزمني مع الموظف والوقت.

### 3.5 المواعيد
- **AC-APT-01** من داخل المحادثة «إنشاء موعد» ← موعد مرتبط بالعميل والقناة والحملة، ومرحلة المسار `appointment_booked`.
- **AC-APT-02** تسجيل «لم يحضر» ← مهمة متابعة تلقائية (إن فُعّلت) + تحديث تقرير الحضور.
- **AC-APT-03** تذكير قبل 24 ساعة ← يُرسل بقالب معتمد وبتوقيت الفرع، فقط لمن ليس في قائمة الإيقاف.

### 3.6 المكالمات
- **AC-CALL-01** مكالمة فائتة ← سجل + مهمة معاودة اتصال للموظف المناسب + ظهور في لوحة المجمع.

### 3.7 التقارير
- **AC-RPT-01** أرقام اليوم (استفسارات، FRT الوسيط، حجوزات، حضور) تطابق عدًّا يدويًا من السجلات الوهمية بنسبة 100%.
- **AC-RPT-02** كل رقم إسناد غير مؤكد موسوم «تقديري» مع توضيح.
- **AC-RPT-03** التصدير يحترم صلاحيات المستخدم ونطاق فرعه ويُسجّل في التدقيق.

### 3.8 التسويق والموافقات
- **AC-MKT-01** إرسال قالب تسويقي لعميل بلا موافقة تسويقية ← مرفوض في الخادم.
- **AC-MKT-02** رد العميل بكلمة إلغاء (مثل «إيقاف»/STOP) ← إضافته لقائمة الإيقاف تلقائيًا + سجل.

### 3.9 الاشتراكات
- **AC-SUB-01** مالك المنصة ينشئ مجمعًا في السعودية بباقة «الاحترافية» تجربة 14 يومًا (المدة قرار Q-06) ← يُرسل دعوة للمدير.
- **AC-SUB-02** انتهاء التجربة دون دفع ← `past_due` ← بعد المهلة قراءة فقط، دون حذف أي بيانات.
- **AC-SUB-03** تكرار webhook الدفع ← فاتورة/تجديد واحد فقط.
- **AC-SUB-04** محاولة دعوة المستخدم رقم 11 في باقة حدها 10 ← رسالة واضحة + خيار الترقية.

### 3.10 الهوية والواجهة
- **AC-UI-01** مدير المجمع يرفع شعارًا ويختار لونًا ضعيف التباين ← يُقترح بديل ناجح، ويظهر الشعار لموظفيه فقط.
- **AC-UI-02** تبديل اللغة ← كل النصوص تتغير والاتجاه ينقلب دون نصوص ثابتة متبقية (فحص آلي للمفاتيح).
- **AC-UI-03** الوضع الداكن ← لا نص بتباين < 4.5:1 (فحص axe).
- **AC-UI-04** كل الشاشات P0 قابلة للاستخدام على عرض 360px.
- **AC-UI-05** البيانات الوهمية تحمل شارة «بيانات تجريبية» في كل شاشة.

## 4. معايير القبول غير الوظيفية

| الرمز | المعيار | طريقة القياس |
|---|---|---|
| AC-NFR-01 | فتح الوارد < 1.5 ث (p75) | Lighthouse/RUM في staging |
| AC-NFR-02 | 50 موظفًا متزامنًا، 20 رسالة/ث لمجمع | اختبار حمل k6 |
| AC-NFR-03 | استعادة نسخة احتياطية ضمن RPO 15 د / RTO 4 س | تمرين موثّق |
| AC-NFR-04 | تغطية اختبارات ≥ 80% لوحدات auth/rbac/tenancy/billing | تقرير CI |
| AC-NFR-05 | صفر ثغرات حرجة/عالية | اختبار اختراق خارجي |
| AC-NFR-06 | لا محتوى رسائل أو أرقام هواتف في السجلات | فحص آلي لعينات السجلات |
| AC-NFR-07 | لا أسرار في المستودع | gitleaks في CI |
| AC-NFR-08 | قائمة بكل التبعيات ورخصها | تقرير آلي في المستودع |

## 6. مقاييس نجاح التجربة (بعد 4–8 أسابيع)
- انخفاض الوسيط لزمن أول رد مقارنة بخط الأساس.
- صفر استفسارات بلا تعيين لأكثر من ساعة عمل.
- نسبة الاستفسارات المسندة لمصدر معروف ≥ 80%.
- استخدام يومي من ≥ 80% من الموظفين المدعوين.
- استعداد المجمع للدفع بعد التجربة.
