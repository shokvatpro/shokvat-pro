# التدويل والتشغيل متعدد الدول — شوكفات برو
**INTERNATIONALIZATION.md** · الإصدار 0.1 (مسودة للاعتماد)

> جميع المعلومات القانونية والضريبية ومزودي الاستضافة أدناه **نقاط بداية للتحقق** وليست استنتاجات نهائية. تتغير الأنظمة والأسعار والمناطق السحابية، ويجب تأكيدها مع مستشار قانوني ومحاسب محلي قبل كل إطلاق.

---

## 1. المبدأ
منصة واحدة قابلة للتكوين، وليست سبعة تطبيقات. كل ما يختلف بين الدول يأتي من **ملف تكوين الدولة** و **محوّلات (Adapters)**، لا من تفرعات `if (country === 'EG')` داخل منطق العمل.

---

## 2. اللغة والاتجاه

| البند | القرار |
|---|---|
| اللغات | `ar` (افتراضية) و `en`؛ البنية تسمح بإضافة لغات |
| الاتجاه | `dir` على `<html>` من اللغة؛ مستقل عن الدولة |
| المستوى | لغة الواجهة **لكل مستخدم**؛ لغة رسائل العميل **لكل عميل** (`preferred_locale`) |
| الأنماط | خصائص CSS المنطقية فقط (`margin-inline-start`، Tailwind `ms-/me-/ps-/pe-/start-/end-`)؛ قاعدة lint تمنع `left/right` |
| الأيقونات الاتجاهية | الأسهم والـ chevrons تنعكس في RTL؛ أيقونات الوقت والتشغيل لا تنعكس |
| النص المختلط | عزل الأرقام والهواتف والبريد بـ `dir="ltr"` / `<bdi>` داخل نص عربي |
| الجمع | ICU plurals (العربية 6 صيغ) |
| الأرقام | قرار افتراضي: **أرقام لاتينية (0-9)** في الواجهة لسهولة الأرقام والهواتف، مع خيار للأرقام العربية-الهندية لكل مستخدم — **(Q-09)** |
| التقويم | ميلادي افتراضيًا؛ عرض هجري اختياري في السعودية |
| البحث العربي | تطبيع: إزالة التشكيل والتطويل، توحيد (أ/إ/آ ← ا)، (ة ← ه)، (ى ← ي) |
| الترجمة | مفاتيح دلالية (`inbox.status.waiting_customer`)؛ فحص في CI لمنع مفاتيح ناقصة |

## 3. ملف تكوين الدولة (`packages/country-config`)

```ts
type CountryConfig = {
  code: 'SA' | 'EG' | 'AE' | 'KW' | 'QA' | 'BH' | 'OM';
  launchStatus: 'closed' | 'planned' | 'legal_review' | 'pilot' | 'live';
  defaultLocale: 'ar' | 'en';
  timezone: string;                 // IANA
  currency: string;                 // ISO 4217
  phone: { callingCode: string; validator: 'libphonenumber' };
  weekend: number[];                // أيام العطلة الأسبوعية
  holidaysSource: 'manual';         // جدول عطل يدوي يحدّثه مدير المنصة
  dataRegion: string;               // 'sa-1' …
  tax: { adapter: string; profileId: string };       // لا نسب ثابتة في الكود
  payment: { adapter: string | null };
  messaging: { whatsapp: boolean; meta: boolean; tiktokLeads: boolean; tiktokDm: boolean; voiceAdapter: string | null; smsAdapter: string | null };
  privacy: { retentionPolicyId: string; marketingConsentRequired: true; callRecordingAllowed: 'no' | 'with_notice' | 'with_consent' };
  invoice: { numberingScheme: string; requiredFields: string[]; eInvoicing: string | null };
};
```
- التكوين مخزّن في قاعدة Control (قابل للتعديل من «إدارة الدول») مع قيم افتراضية في الكود.
- **لا يُفعَّل التسجيل المدفوع لدولة** إلا إذا كانت `launchStatus ∈ {pilot, live}` واكتملت قائمة بوابة الإطلاق (COUNTRY_LAUNCH_CHECKLIST).

## 5. العملات والتسعير
- السعر محدد يدويًا لكل (باقة × دولة × فترة) في `plan_prices` — **لا تحويل فوري** للعملات.
- أسعار السعودية المبدئية: 699 / 1,299 / 2,499 ر.س شهريًا (نقطة اختبار). الدول الأخرى تُسعَّر بعد مقابلات السوق.
- الخصم السنوي: مقترح شهرين مجانًا (= 10 أشهر) — **(Q-05)**.
- رسوم القنوات (رسائل واتساب، دقائق الاتصال) تُمرَّر بتكلفتها + هامش اختياري، تظهر منفصلة، مع حد إنفاق شهري يضبطه المجمع.
- عرض المبالغ بـ `Intl.NumberFormat` حسب اللغة والعملة؛ الحساب بالوحدات الصغرى فقط.

## 6. استراتيجية البنية الدولية

### 6.1 Global Control Plane
- موقع واحد يُختار بعد مراجعة قانونية بحيث لا يحتوي إلا بيانات C1 (اشتراك) + هوية الموظفين (قرار Q-11).
- مقترح: نفس منطقة السعودية في البداية لتقليل أسئلة النقل عبر الحدود لأول سوق.

### 6.2 Regional Data Planes
| المنطقة | الدول | الحالة |
|---|---|---|
| `sa-1` | السعودية | MVP |
| `eg-1` | مصر | بعد المراجعة القانونية |
| `ae-1` | الإمارات | بعد المراجعة القانونية |
| `gcc-x` | قطر/البحرين/عُمان/الكويت | تُقرر لكل دولة: منطقة مستقلة أو مشتركة **فقط إذا سمح القانون** |

### 6.3 مزودو الاستضافة — مرشحون للتحقق (لا توصية نهائية)
- **السعودية:** عدة مزودين عالميين ومحليين أعلنوا مناطق داخل المملكة (مثل Google Cloud، Oracle Cloud، Microsoft Azure، Huawei Cloud، Alibaba Cloud، ومزودون محليون مثل STC Cloud). يجب التحقق من: إتاحة Managed PostgreSQL و Redis و KMS وObject Storage فعليًا في المنطقة، وشروط التعاقد، ومتطلبات تنظيمية للتصنيف الحكومي إن وُجدت.
- **مصر:** حضور محدود لمناطق المزودين العالميين؛ قد يلزم مزود محلي أو نقل بيانات بتقييم قانوني.
- **الإمارات/قطر/البحرين:** توجد مناطق لعدة مزودين عالميين؛ تحقق من القواعد الخاصة بالبيانات الصحية (خاصة الإمارات).
- **قاعدة:** لا نفترض أن الاستضافة داخل الدولة تحقق الامتثال تلقائيًا. القرار = (قانون) + (توفر خدمات) + (تكلفة).

### 6.4 تجنّب القفل على مورد
- كل خدمة سحابية خلف واجهة: `StorageAdapter`، `KmsAdapter`، `QueueAdapter` (BullMQ/Redis قياسي)، Postgres قياسي.
- البنية ككود بوحدة لكل مزود؛ نقل منطقة = نقل بيانات + تطبيق وحدة أخرى.

---

## 7. الهاتف والرسائل
- تخزين الأرقام بصيغة **E.164** والتحقق بـ libphonenumber.
- عرض الرقم بالصيغة الوطنية حسب دولة العميل، داخل `dir="ltr"`.
- مزود الاتصالات والرسائل النصية لكل دولة عبر `VoiceAdapter` / `SmsAdapter`.
- قواعد الرسائل التسويقية وأوقات الإرسال المسموحة لكل دولة في `privacy` (تُحدّد قانونيًا).

## 8. التاريخ والوقت
- التخزين UTC؛ العرض بتوقيت **الفرع** للمواعيد، وبتوقيت **المستخدم** للأنشطة.
- ساعات العمل والعطل لكل فرع؛ SLA يُحسب بساعات العمل فقط (قابل للتعطيل).

## 9. إطلاق دولة جديدة (إجرائيًا)
1. إكمال قائمة COUNTRY_LAUNCH_CHECKLIST.md وتوقيع المسؤولين الثلاثة.
2. إنشاء `tax_profile` و `retention_policy` و `plan_prices`.
3. نشر Data Plane (إن لزم) عبر وحدة OpenTofu.
4. تفعيل المحوّلات (دفع، اتصالات) في staging واختبارها.
5. تشغيل اختبارات العزل الإقليمي.
6. تغيير `launchStatus` إلى `pilot` ← 2–3 مجمعات تجريبية ← `live`.
